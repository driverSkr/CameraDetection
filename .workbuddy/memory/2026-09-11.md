**Ardot 踩坑记录（复用价值高）**
1. 变量引用必须写 `$:Design Tokens:<name>`；直接写 `$<name>` 会报 invalid color
2. `insert` 操作里传渐变 fill（`fill:{type:"GRADIENT_*"}`）会报 "Failed to parse node data"，需先插纯色再批量 `U` 改
3. `layout:"none"` 父级下子元素用 x/y 绝对定位；若父级是 flex 布局，需 `layoutPositioning:"ABSOLUTE"` 才能让 x/y 生效
4. 徽章类小元件若写成 `FRAME` + `width:100 height:100`，会渲染成一坨大色块；必须 `layout:"horizontal"` + `width/height:"hug_contents"` + `padding`
5. 大面积装饰圆（光晕/波纹）不要用实心浅灰填充，会非常刺眼；波纹用 `fills:[]`（纯描边），光晕用深色 + 降 opacity
6. 容器高度不足会静默裁剪子内容（映射表 680 高装不下 13 行 → 改 880）
7. 圆角矩形做分隔线要显式指定暗色，默认浅灰在深色 UI 上会变成刺眼白线

- 上传链路：`register_assets` 取 uploadUrl/downloadUrl → Python urllib PUT 上传 → `upload_images` 按 nodeId 应用

**Ardot 新踩坑**
1. `U(id, {svg:"..."})` 更新 SVG **不生效**（返回 `updated:{}`）——必须 `D(id)` 删除后重新 `I()` 插入
2. `strokes` 的 color 不能带 `a` 键（`{r,g,b,a}` 报 Unrecognized key 'a'），要用 `{r,g,b}` + 同级 opacity
3. `ellipse` 小写可作为 insert 的 type
4. Python urllib 是本环境最可靠的下载/上传通道（bash 的 curl/mkdir/dirname 不可用）
5. 构建策略：屏幕根节点用 `layout:"none"` 精确落位模块，模块内部用 flex 布局排元素——比纯 flex 更可预测，比纯绝对定位更少错位
