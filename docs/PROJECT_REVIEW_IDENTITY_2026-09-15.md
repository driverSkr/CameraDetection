# 项目复查：身份识别、扫描流程与体验

## 范围与结论

检查当前工作区的扫描调度、取消/网络变化处理、服务发现、身份查询、分类、结果筛选、历史保存、相机生命周期、磁场监听和安全提示页面。本轮仅审查，未修改应用代码。

发现 5 项可从代码确认的问题，均为 P2（应修复，非立即阻断运行）。另有 1 项性能优化机会，尚未测量实际耗时收益。没有证据表明它们解释了上一轮全部 139 台待确认设备；需要认证或未提供身份信息仍是识别限制。

## 1. 描述地址被按展示文本截断

- 位置：`scan/ServiceMetadata.kt:5`、`:9`；`scan/NetworkScanner.kt:70`。
- `clean()` 将所有字段限制为 200 字符。SSDP 的 LOCATION 在解析头部时被截断；ONVIF 地址进入 metadata 时也被截断。`DeviceDescription.localUrl()` 原本允许 2048 字符，但到达它或读取阶段的值已经可能不完整。
- 触发：合法同源地址长度超过 200 字符，且末尾路径或查询参数是获取描述所必需的。截断后可能访问错误地址或解析失败，最后显示描述不可用。
- 建议：协议字段与展示字段分离；地址完整验证、独立限长，超长则拒绝，不静默修改地址。
- 验证用例：长路径、长查询参数、百分号编码边界，确认请求地址与公告完全一致。

## 2. 同端口的不同描述地址被当作同一任务

- 位置：`scan/MdnsDiscovery.kt:105`；`scan/NetworkScanner.kt:70-77`、`:152`、`:234`。
- ServiceProbe 只包含端口与协议。URL 单独存在每个 IP 的一个可覆盖字段中；是否重新分析只比较 ServiceProbe 集合。
- 触发：同一 IP 先公告 `http://IP:80/a.xml`，完成查询后再公告 `http://IP:80/b.xml`。metadata 更新到 b，但端口和协议没变，不会重新排队。分析结果仍来自 a。多个端口的描述任务也都在执行时读取同一个 URL 槽位，可能重复查询最后一个地址。
- 影响：描述遗漏、查询任务与地址不一致，身份结果取决于公告时序。
- 建议：每个描述任务携带已验证的不可变 URL，并将完整端点纳入去重键；查询结果按来源存储，明确合并规则。

## 3. 多种 mDNS 身份提示相互覆盖

- 位置：`scan/MdnsDiscovery.kt:153-155`；`scan/NetworkScanner.kt:70`；`scan/DeviceIdentity.kt:41`。
- 同一 IP 的所有服务共用 mdns_name、mdns_host、mdns_device_type 字段。地图合并保留最后一个值，未保留类型候选集合。
- 触发：同一主机公告打印服务和 AirPlay/Cast 服务，最后写入的类型成为唯一 mDNS 类型。更换公告首次到达顺序即可改变最终类别，分类层也看不到被覆盖的冲突线索。
- 建议：按服务实例保留名称和类型集合，区分服务能力与硬件身份；对多能力设备明确展示多个服务或保留硬件待确认。增加公告顺序交换的回归用例。

## 4. 加密打印服务收到明文 HTTP 探测

- 位置：`scan/MdnsDiscovery.kt:150`；`scan/NetworkScanner.kt:242-249`。
- 除 RTSP 外，所有已支持的 mDNS 服务都映射到 HTTP，包括 `_ipps._tcp`。分析器随后在普通 Socket 上发送明文 HEAD。
- IPPS 使用 HTTPS/TLS，参见 [RFC 7472](https://www.rfc-editor.org/rfc/rfc7472.html)。当前请求不能完成该服务的有效协议验证，设备可能关闭连接或导致读取超时；即使 mDNS 已识别为打印服务，也可能被计为分析未完成。
- 建议：根据公告协议选择探测方式；尚未实现的协议保留公告信息，标明未做协议验证，不把不适用的探测失败当成设备异常。
- 验证范围：协议映射缺陷已由代码确认；具体打印机响应及额外耗时尚未做真机测量。

## 5. 安全提示的展开和返回按钮缺少无障碍说明

- 位置：`ui/tips/page/TipsPage.kt:50`、`:72`、`:120`、`:168`。
- 可点击 Image 的 contentDescription 为 null，没有展开/收起状态；只有箭头可展开，栏目标题不可点击。读屏用户难以知道按钮控制哪一栏。
- 建议：整行作为栏目开关，合并标题语义，提供展开状态；返回按钮补充名称。标题容器由固定 24dp 改为按文字适应高度。
- 代码确认无障碍语义缺失；大字体截断程度仍需特定字号下验证。

## 性能优化机会（未量化）

`scan/NetworkScanner.kt:395` 每收到一个 mDNS 数据包，都重新枚举全部缓存端点并调用 discovered；未变化的端点也重复合并证据、创建设备记录并进入同步锁。多服务网络中存在重复计算。

建议只发布新增或发生变化的端点，并单独处理撤销；用固定数据包序列对比 discovered 调用次数、分配量和处理耗时。当前没有证据证明这已造成可感知卡顿，不能直接承诺缩短完整扫描时间。
