# Wi-Fi 提速后项目复审

## 结论

本轮未确认新的 P0/P1 阻断问题，发现 3 项 P2 改进和 2 项 P3 问题。此次检查新增复现测试和报告，没有修改业务逻辑。订阅绕过仍视为当前明确保留的测试配置，不列为缺陷。

范围：Wi-Fi 地址规划、并发、设备分析、组播、取消与生命周期、历史保存和恢复、相机状态与控制、磁场采样、页面布局、订阅与启动流程。未执行真实购买、支付取消、相机硬件故障注入或所有 Android 版本兼容性测试。

## P2：组播发现缺少有限重试，单次丢包可能遗漏非标准端口设备

- 位置：`NetworkScanner.kt:281–299`、`MdnsDiscovery.kt:125–134`。
- mDNS、SSDP、ONVIF 初始请求各发送一次，接收窗口为 2 秒。mDNS 的缺失 SRV/A 查询加入 `asked` 后，本次扫描不会再发送同一问题；接收超时只是继续等待。
- 条件：初始请求或回复丢失，或 mDNS 分包解析中的一次回复丢失。使用非默认端口、依赖服务公告发现的设备可能无法被默认五端口扫描补回。
- 已有 `joinsSplitPacketsAndQueriesOnlyMissingRecords` 测试明确验证同一问题第二次调用不再返回。未在真实路由器上进行可控丢包实验，不能量化现实漏检率。
- 建议：为初始发现及未解析服务增加少量、带间隔的重试，区分“已发送”和“已解析”；保持与 TCP 扫描并行和资源上限，避免再次采用已验证不合适的 TCP 快速探测方案。

## P2：设备详情的大字号布局会让标签与数值重叠

- 位置：`dialog/view/WifiInfoDetailsView.kt:72–83`。
- IP、MAC 和设备型号使用固定高度的 Box，左右文本各自对齐，没有分配互不重叠的宽度。
- 真机复现：360×480dp 的组件视口、英文、2 倍字体，IP `192.168.255.254`。标签右边界 451px，地址左边界 429px，重叠 22px（约 8dp）。未改手机的系统字号或分辨率。
- 复现测试：`ReauditEvidenceTest.reproducesIpLabelOverlappingAddressAtLargeFont`。
- 建议：改为可换行的 Row/Column；长地址或大字号时上下排布；高度由内容决定。列表和其他固定高度信息行可一并回归检查，但本轮只将详情 IP 重叠列为已复现问题。

## P2：历史读取失败被当成“没有历史”，缺少恢复提示

- 位置：`utils/ScanHistoryStore.kt:45–63`。
- 文件读取/解码异常通过 `getOrNull()` 丢弃；没有可用旧格式记录时返回空 `ScanArchive`。现有 `saveFailed` 只描述写入失败。
- 条件：历史内容损坏或来自不支持的版本。用户看到无历史，无法分辨读取失败。后续正常扫描保存还会替换原文件，失去进一步恢复原文件的机会。
- 隔离复现：在测试专用临时目录写入不支持版本的历史；调用 `load()` 正常返回空档案，没有返回读取失败状态。测试不读写用户真实历史文件。
- 建议：区分不存在、读取失败和版本不兼容；保留异常原文件或备份，给出“历史暂时无法读取”提示和重试入口。

## P3：订阅价格重试成功后仍显示上次失败提示

- 位置：`ui/subscribe/viewmodel/SubscribeViewModel.kt:39–53`、`ui/subscribe/page/SubscribePage.kt:210–212`。
- 第一次请求超时后 `messageRes` 被设为错误；重新加载成功并得到非空商品时只更新 `products` 和 `selected`，没有清理该错误。页面继续显示错误文本，与可购买的商品卡片冲突。
- 证据：代码状态路径；未进行真实商店失败/恢复注入。
- 建议：将商品加载错误与购买状态提示分开管理，成功加载时只清理商品加载错误，保留仍有效的价格变化/购买提示。

## P3：部分纯图标按钮缺少无障碍名称

- 位置示例：设备详情关闭按钮 `WifiInfoDetailsView.kt:69`；相机页返回、关闭帮助、重置按钮；设置页返回按钮。
- 这些 Image 使用 `clickable`，但 `contentDescription = null`，也没有替代的文本语义。辅助阅读用户无法获知按钮用途。
- 建议：补上中英文本地化操作名称，检查触控区域。已有滤镜选择和相机帮助入口的语义可以沿用。

## 可选体验与性能优化

- 扫描进行中提供“查看已发现设备”入口，同时明确显示仍在扫描；目前只能看线索数量并等待结束，才能查看详情。此项不应通过切页面终止扫描。
- 首次引导最后一页即发起评分请求（`GuidePage.kt:62`），用户尚未体验扫描；可改为完成一次有意义的操作后再触发。
- Wi-Fi 并发目前依据地址数为 32/48/64，并非根据实时链路质量自动调整。建议先记录多种路由器和设备上的错误率及耗时，再考虑自适应，不继续盲目增加并发。

## 验证与排除

- 本轮 106 个单元测试通过；原有 7 个真机测试通过；新增 2 个证据测试用于证明上述布局和历史读取问题存在。证据测试通过不代表缺陷已修复。
- 完整回归日志：`app/build/reaudit-after-speed.log`；补充证据日志：`app/build/reaudit-evidence.log`。
- 业务代码没有变更，沿用上一轮 Lint 结果：0 错误、114 个警告、1 条信息；本轮未重新跑 Lint。
- 上一轮同机同网段提速结果为 133.3 秒降至 67.6 秒、2046 地址、189 台设备、28 个摄像头线索。这是此前实测，本轮没有重复运行完整 LAN 性能测试。
- 正常结果页隐藏底部导航，因此最初怀疑的“结果页→功能→Wi-Fi 导致请求卡住”在正常路径下不能触发，未列为缺陷。
- 建议修复顺序：详情可读性与历史恢复提示 → 组播有限重试及可控丢包测试 → 订阅提示与无障碍 → 可选体验改进。
