## 性能优化

### 设备快照

增加按 IP 更新的设备快照缓存。只有设备证据或分析状态发生变化才更新对应设备，并在需要发布时重新排序；纯进度变化复用同一份快照。主线程收到相同快照时跳过信任映射、复制及列表替换。

历史检查点也复用未变化的设备快照。用户信任标记变化会使缓存失效；测试确认不会把新信任状态丢掉，也不会改写旧记录对象。

在桌面 JVM 的 4096 设备模拟测试中，完整复制/排序路径约 **3.21 ms/次**；优化后的无变化轮询直接复用对象，测试确认不再重建列表。这里验证的是缓存路径，不能等同于真机帧率或耗电改善幅度。

### 历史编码与持久化

- 使用 V3 档案格式，最近记录和完整记录通过 ID 引用数据，同一记录只存一份。
- 最多缓存当前两条记录；设备未变化时复用已编码、已校验的设备数据，只处理变化的时间、覆盖数量和状态等元数据。
- 新档案写入应用私有目录的 `scan_history_v3.json`，先写入并同步临时文件，再原子替换。写入/替换失败时保留旧文件并显示已有保存失败与重试提示。
- 新旧数据分开存储，避免新检查点反复重写旧 SharedPreferences 档案。原 V2 和旧键不删除，读取时仍可兼容和回退；也兼容中间测试版的 V3 偏好存储。
- 保留后台串行写入、合并排队、设备与元数据校验、最近/完整记录分离、用户信任标记隔离。

| 模拟设备数 | 原双记录 JSON | 新去重 JSON | 原编码+解码均值 | 新编码+解码均值 | 新缓存检查点编码及校验均值 |
