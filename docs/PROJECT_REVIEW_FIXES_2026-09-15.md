# 复查问题修复

## 已实现

1. **完整描述地址**：LOCATION 使用独立的 2048 字符上限，超限拒绝，合法地址不再经过 200 字符的展示文本裁剪。ONVIF/UPnP URL 直接由任务持有，不再经 metadata 清洗。
2. **端点去重**：ServiceProbe 包含 URL，同 IP、同端口、不同路径各自排队；执行时读取任务自身地址，避免读取被后续公告覆盖的共享字段。原有最多 8 个公告任务及全局 8 并发上限保留。
3. **多来源身份**：mDNS 名称、主机名和类型使用有界、排序、去重集合，顺序不再决定唯一类型。多种服务能力且缺乏更强身份依据时保留硬件待确认。描述查询保留一个完整主报告及其他来源报告，不拼接来自不同设备描述的型号/固件；型号或公告类型冲突时提示核实。部分查询失败不抹去成功取得的信息。
4. **协议匹配**：打印、投屏等没有专用应用协议验证器的服务只做 TCP 连接验证，保留公告能力；不再一律发送 HTTP HEAD。只有明确 HTTP/ONVIF、RTSP 服务使用相应请求。公告只说明服务能力，不等于硬件认证。
5. **安全提示体验**：整行可点击展开、提供按钮角色和展开/收起状态、返回按钮有名称；标题支持自适应高度，展开状态可跨配置重建保存。
6. **重复处理**：mDNS 只把新增或变化的端点送入 discovered，重复数据包不再重复更新设备行。收到撤销记录后更新发布缓存，后续重新公告可再次发布；本次扫描已经观察到的线索仍作为历史观察保留。
