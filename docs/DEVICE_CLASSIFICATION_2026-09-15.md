# 设备身份分类与描述查询

## 已完成

- 将设备身份与摄像头线索分离：视频协议仍作为线索保存，不把 RTSP、端口号或通用 `webserver` 描述直接当作摄像头类型。
- 类型包括本机、路由器、媒体播放设备、媒体服务器、打印机、疑似网络摄像头、疑似录像机及类型待确认。
- UPnP 使用设备公告的 deviceType；mDNS 增加 IPP/IPPS、AirPlay、Google Cast 服务发现，分别辅助识别打印机及媒体播放设备。新增公告不会被误记为摄像头证据。
- 摄像头/录像机只在设备型号包含明确类型词时给出“疑似”判断，不能据此确认设备实际用途。
- 名称优先使用 UPnP 名称，其次 mDNS 名称和设备型号。列表显示名称、IP、类型；详情显示分类依据及信息来源。
- 结果页增加类型筛选与数量，方便直接查看媒体设备、打印机或待确认设备。原有摄像头线索数量仍独立保留。
- 旧历史按已有证据展示身份，新描述信息需要重新扫描获取。

## 设备描述采集

查询 SSDP 公告的 UPnP 设备描述，以及 ONVIF 公告端点的 GetDeviceInformation。采集设备名称、制造商、型号和固件（取决于设备返回内容）。需要认证时明确显示“设备要求登录”，不尝试默认密码。

仅接受与公告源 IPv4 地址完全一致的 HTTP URL，不接受账号信息、外部域名、其他 IP 或自动重定向；不查询未公告的猜测路径。连接限时 1000ms，总读取截止时间 2500ms；限制响应头和正文，正文最大 64KB。与现有设备分析共用 8 个并发资源，取消时关闭网络连接。XML 拒绝 DTD/实体声明，读取对应命名空间中的设备自身字段，不把子设备的型号归给父设备。

摄像头线索仍为 **28** 台。**26** 台设备的身份查询返回需要认证，因此没有强行补写品牌或硬件类型。不同轮次在线设备数量会变化，单次扫描不能证明完全召回。

实际公告示例：`100智慧屏BB-DLNA`（制造商描述 `Skyworth-Coocaa`，型号描述 `Skyworth Media Renderer`）、`Transcreen-21391`，均被归为媒体播放设备。这些是设备自报信息，不是品牌真实性认证。
