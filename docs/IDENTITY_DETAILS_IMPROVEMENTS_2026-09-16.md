# Wi-Fi 设备身份与详情页复查

本轮在前两项修复基础上，检查设备公告收集、身份分类、列表/详情展示和操作建议，完成以下优化。

## 已修复和改进

1. **利用已取得的 SSDP 类型公告。** 原先分类只读取设备描述中的 UPnP 类型，忽略已记录的 `ssdp_st`；当描述读取失败时，即使公告明确声明打印机或路由器，仍可能显示类型待确认。现在按严格匹配的设备类型声明识别，并显示 SSDP 来源。媒体播放、媒体服务器公告用于展示服务能力，不据此推断电视、摄像头等硬件。
2. **保留多份 SSDP 类型。** 原先新的公告覆盖旧的 `ssdp_st`，例如后来的 rootdevice 公告会抹去先前的设备类型。现在按有界集合合并，去重排序，避免依赖公告到达顺序；不同来源的明确硬件类型矛盾仍提示冲突。
3. **明确待确认的原因。** 详情页按已取得型号、已识别服务、视频服务、访问受限、身份冲突分别展示状态。已知厂商、型号和服务能力默认显示，不必展开技术详情。无名称设备以“网络设备”为标题，避免标题与状态重复。
4. **匹配下一步建议。** 已识别设备不再使用“缺少身份信息”的通用建议；未匹配的型号、身份冲突分别提示核对机身标签、路由器设备列表或来源报告。未完成检查、视频线索和访问受限的提示继续保留。

## 识别边界

不从厂商品牌、开放端口或通用软件横幅猜测硬件类型；服务能力不等同于硬件类型。没有提供可用身份的设备仍会显示暂未识别，不能保证每台设备都能自动分类。已有历史中保存的结构化公告可被新的展示逻辑利用，但此前未记录或被覆盖的信息需要重新扫描取得。

## 验证

新增 8 项单元测试，覆盖公告合并、描述不可用时的识别、严格匹配、冲突处理及状态/建议；新增 2 项真机页面测试，覆盖中文默认信息、技术详情展开，以及 360×480 dp、2 倍字体下的滚动和标记按钮。

日志：`app/build/identity-details-review.log`、`app/build/identity-details-device-tests.log`。页面测试使用构造的设备数据，不代表已完成真实局域网设备识别率对比。

完整回归结果：148 项单元测试、20 项 PLY110（Android 16）真机仪器测试全部通过，构建成功；Lint 0 个错误、120 个警告、2 项提示。真机测试启动时曾被系统冻结进程，通过正常启动入口恢复后测试完成，未修改系统省电设置。已人工查看中文页面测试截图 `app/build/identity-details-zh.png`，确认已知信息和下一步建议正常显示。
