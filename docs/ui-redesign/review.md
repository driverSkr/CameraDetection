# SpyFinder 全应用 UI 审核与原型说明

审核日期：2026-09-11。依据当前工作区源码进行页面、交互、状态与实现边界审核。已阅读全部业务页面、入口 Activity、主要弹窗、检测逻辑、最近结果存储、权限与订阅调用链，并检查 Manifest、Gradle 与主题配置。公共库完成职责梳理，未逐行审计其全部实现。

本轮产出为 UI 原型和审核报告；没有替换 Android 页面，也没有运行 APK、真机传感器、网络扫描或实际购买。以下区分源码可确认的问题与需要运行验证的风险，不将本报告视为全量安全、性能或支付正确性认证。

## 一、方案定位

方案名：Quiet Check。温和、清晰、可信的隐私检查工具。

- 用暖灰背景、深墨绿文字、白色信息面板、薄荷绿强调色替换当前黑底、发光雷达、重图片界面；同时给出深色适配。
- 保留现有四个入口：Wi-Fi / Magnetic / Scanner / Tools。分别对应 Detect / Sensor / Scanner / Feature，索引和功能不变。
- 沿用现有英文产品语言，原型的审阅标签与说明使用中文。正式落地时把硬编码文字抽到资源文件。
- 每屏只突出一个主要操作，设备信息、异常恢复、订阅权益使用同一组组件。
- 展示真实能力：网络设备排查、磁场读数、相机滤镜辅助检查。避免把未知设备、滤镜亮点或磁场变化直接表述成隐藏摄像头。
- 不新增账户登录、云同步、多次历史记录、摄像头定位、自动识别、拍照存档等当前不存在的产品能力。

## 三、优先处理的发现

以下路径统一相对于 `app/src/main/java/com/spyfinder/hiddencamera/detectorapp/`。P1 为影响结果可信度或核心流程的问题；P2 为体验、可维护性及边界问题。

### 1. P1：磁场归一化值被标成 μT（源码确认）

位置：`ui/main/page/SensorPage.kt:111–119, 259`。

传感器先算出真实磁场 magnitude，再映射到 0–100，最终将 normalizedValue 存入 magneticGauge，却在文本后追加 μT。例如真实值 50 μT 会被映射成 3，再显示成 3 μT。应分别保存 rawMicroTesla 和 normalizedGauge；大数字只显示原始读数，仪表进度才使用归一化值。原型中的 46.2 μT 是建议修正后的示例读数。

### 2. P1：所有非本机设备默认进入“可疑”，结果文案误导（源码确认）

位置：`utils/WifiHelper.kt:91–117`；`ui/main/view/DetectResultView.kt:129, 155`。

默认 riskLevel = 1，仅本机 IP 改为 0。端口识别类型后没有对应风险校正，因此路由器、电视或普通电脑也进入可疑列表。现有 “Risky devices Found” / “Safe” 不能表达这一实际规则。新稿改为 “Needs review” / “This phone & confirmed”，设备类型标记为推断。若将来要展示风险证据，必须额外保存实际检测依据，不能只改标题。

### 3. P1：扫描错误与成功空结果共用返回（源码确认）

位置：`ui/main/view/DetectCheckView.kt` 的 `wifiDetect()` 异常分支，最终调用 `onDetectFinished(emptyList(), emptyList())`。

扫描启动异常会被当作完成并保存空快照，用户无法区分“没找到设备”与“没有完成扫描”，还可能覆盖上一次结果。建议返回 Success / Failure / Partial 等显式状态；失败不覆盖最近成功记录。新稿分别提供 No devices found 与 Check interrupted。

### 4. P1：切换 Tab 可能中断扫描 UI 状态机（静态风险，待运行复现）

位置：`ui/main/page/MainPage.kt` 的 AnimatedContent；`ui/main/view/DetectCheckView.kt:237` 及 activeScanId 等 remember 状态。

切走 Detect 后其组合离开，进度协程会取消，局部 scanId 状态会重建，而 MainContextEntity 中 isStartDetect / isAnimating 仍在。返回时 activeScanId 从 0 开始，进度 effect 直接返回，旧回调又依赖旧作用域，存在卡在扫描态的路径。应将扫描任务和状态迁到 Activity 级 ViewModel，或在离开时显式终止并恢复待机。原型切换页时停止本地演示计时，不能代替 Android 生命周期验证。

### 5. P1：价格请求失败仍构造可选择商品（源码确认）

位置：`ui/subscribe/viewmodel/SubscribeViewModel.kt:28–67`。

查询失败时仍使用 `$6.99 / $19.99 / $39.99` 构造模型并加入列表，用户看见的价格可能不是商店当前返回的价格。新稿保留这些数字仅作明确标注的示例；正式界面必须基于商店成功返回的可购买商品展示价格，失败显示重试并禁用购买。此报告未查询线上实际报价。

### 6. P2：没有传感器时仍可显示停止检测按钮（源码确认）

位置：`ui/main/page/SensorPage.kt:130` 及 toggleDetectionWithSubscriptionCheck。

magneticSensor 为空时不注册监听，但 isListening 仍可变成 true。应在发起订阅门槛或开始测量前检查硬件支持，展示不可用状态和其他方法入口。

### 7. P2：相机文案与实际操作不一致（源码确认）

位置：`ui/camera/page/CameraScannerPage.kt:100, 120, 131–141`；`ui/camera/view/CameraPreview.kt:58`。

界面提示“press this button to start detection”，实际只有颜色切换和重置。虽然构造了 ImageCapture，但没有 takePicture 调用或 ImageAnalysis。新稿准确称为 Camera inspection，不画自动识别框、快门、检测完成结果或摄像头定位。

### 8. P2：网络“信号”数值来自 ping 与 TTL（源码确认）

位置：`utils/WifiHelper.kt:139–141, 210`。

signal 与 rssi 都来自 estimateSignalStrengthByPingTtl，而不是读取目标设备无线信号。新稿去掉设备距离及信号强弱暗示，保留真正可展示的名称、类型和地址。

### 9. P2：网络分析等待没有完整超时与取消语义（静态风险）

位置：`utils/WifiHelper.kt:117` 的 latch.await；`ui/main/view/DetectCheckView.kt:653` 的逐线程 join(3000)。

一个端口扫描若没有完成回调，设备分析线程会持续等待；外层超时后可以保存不完整快照，用户看不到该区别。建议有限并发、超时、统一取消及不完整结果状态。实际概率与第三方库行为需在设备和异常网络环境验证。

### 10. P2：权限请求与冷启动订阅存在时序竞争（源码可见，待运行验证）

位置：`ui/main/MainActivity.kt:54–55, 74`。

onCreate 同时触发异步订阅检查和 Wi-Fi 权限申请，可能出现先后弹窗打断。拒绝时只显示 Toast。建议在用户点击扫描后先解释权限，再请求；普通拒绝允许重试，永久拒绝打开应用设置；返回页面重新检查并恢复原操作。原型的统一“设置恢复态”展示永久拒绝路径，正式代码应区分两种拒绝。

### 11. P2：密度覆盖与固定布局限制适配（静态风险）

位置：`theme/Theme.kt:75`；`ui/guide/page/GuidePage.kt:90, 94`；各主页面的固定尺寸 Box 和偏移。

全局用屏幕像素宽 / 393 覆盖 density，多个页面再叠加固定高度、居中大图与底部控件。短屏和大字号下存在重叠或裁切风险。建议使用原生 dp、系统 fontScale、滚动内容与固定操作区组合，避免靠整体缩放解决布局。

### 12. P2：样式和组件没有使用统一设计体系（源码确认）

位置：`theme/Theme.kt` 及业务各 Page。大量 Color、dp、sp 和英文硬编码，图标点击处常用 contentDescription = null，多个按钮只是一段带 clickable 的 Box。

建议统一 ScreenScaffold、PrimaryButton、ToolRow、DeviceRow、StatusPanel、PermissionPanel、PlanCard；图标按钮增加语义描述与足够触控区域。状态栏前景应依据实际屏幕底色设置，当前 isAppearanceLightStatusBars = darkTheme 与大量固定黑底不匹配。

其他小问题：详情 “ID Address” 应为 “IP address”；“Beside Table” 应为 “Bedside table”；端口分析返回 PC / TV / Apple，而名称生成分支没有完整覆盖这些类型，导致本可识别的类型仍显示 Unknown。Tips 三组正文重复，建议按场景重写。

## 四、原型覆盖清单（32 张）

| 编号 | 页面 / 状态 | 属性 |
| --- | --- | --- |
| 01–03 | Wi-Fi 首页、进行中、完成 | 现有流程重设计；阶段文案需接真实扫描状态 |
| 04–08 | 锁定结果、列表、详情、手动确认后、最近结果 | 保留订阅、确认、最近快照流程 |
| 09–14 | 空结果、无记录、未连接、权限说明、权限拒绝、扫描失败 | 新增或完善状态呈现 |
| 15–17 | 磁场待机、测量中、无传感器 | 前两项保留；读数修复与无硬件态需代码调整 |
| 18–21 | 12 个位置、相机授权、拒绝、预览滤镜 | 保留场景与滤镜，完善授权恢复 |
| 22–24 | 工具、技巧、设置 | 保留入口，统一列表和文案 |
| 25–29 | 订阅、商品加载、商品失败、购买失败、恢复购买 | 完善边界；订阅页恢复入口为建议新增快捷入口 |
| 30–32 | 三页首次引导 | 保持页数及进入订阅的路径 |

原型上方下拉框及左右箭头为审阅工具，不属于 App。选择器可以直接进入任何页面，包括订阅后的状态，以便看图；真实入口点击仍演示订阅门槛。

可体验链路：

1. Wi-Fi → 扫描（3 秒本地演示）→ 完成 → 订阅 → 返回结果 → 设备详情 → 确认。
2. Magnetic → 开始 → 订阅（未解锁时）→ 继续测量 → 停止。
3. Scanner → 任意位置 → 订阅（未解锁时）→ 相机权限 → 红 / 绿 / 蓝 → 重置。
4. Tools → Wi-Fi 直接开始；Tools → Tips 折叠；Tools → Settings → 恢复。
5. 三页引导 → 订阅 → 关闭或模拟购买 → 首页。

模拟购买仅修改原型内存，不连接 Google Play；相机为绘制占位，不申请真实相机权限。系统设置、分享、评分和法律页面只说明跳转目标，不进行外部动作。页面、读数、网络、设备和价格都为示例。

## 六、落地范围分级

第一批：颜色、文字、圆角、间距、卡片、导航、按钮、设置与技巧，使用既有数据结构和事件回调。

第二批：修正磁场读数、将扫描状态迁入 ViewModel、显式异常类型、商品加载可信状态、权限恢复、缺失传感器、超时与取消。原型已经画出这些状态，正式 App 需要实现支持。

保持现有业务约束：结果付费、磁场与相机付费、购买后续接操作、最近一次记录、手动确认仅作用于当前 / 最近结果。首次与冷启动订阅策略不擅自删除。

若要区分“自动识别为本机”和“用户手动确认”，可以使用当前本机 IP 做展示判断；若要在历史中稳定区分来源，则需要增加 confirmationSource 等存储字段。原型的 “Confirmed by you” 来源在本地演示内记录，当前历史模型不能完整还原此语义。

## 七、后续 Android 验收

- 小屏、长屏、横向系统字体放大，检查引导按钮、套餐与导航不重叠。
- 未订阅 / 已订阅 / 查询失败；各入口购买成功后回到正确的操作，关闭不丢失待看结果。
- 扫描中切换 Tab、退后台、返回、重建 Activity，验证不会永久停留在扫描态。
- 无 Wi-Fi、普通拒绝、永久拒绝、权限设置返回；空结果和失败不同，失败不覆盖旧历史。
- 无磁场传感器、实测原始数值、停止 / 离开后注销监听。
- 相机首次授权、拒绝、初始化失败、滤镜重置；不显示不存在的识别结论。
- 新扫描重置确认结果；手动确认同步当前与最近列表；重新启动后读取最近快照。
- 商品成功才允许购买；恢复操作区分成功、无权益、失败；实际金额跟随 Play 返回值。
- TalkBack、图标标签、焦点、48dp 触控区域、深浅主题及状态栏对比。

以上为验收计划，并非本轮已经在 Android 上完成的测试。
